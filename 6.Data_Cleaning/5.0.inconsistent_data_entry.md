# 1. Inconsistent Data Entry কী?

Real-world dataset-এ মানুষ manually data entry করলে একই বাস্তব value-এর একাধিক textual form তৈরি হতে পারে।

### Inconsistency-এর Common কারণ

| কারণ | উদাহরণ |
|---|---|
| Uppercase/lowercase variation | `Dhaka` / `DHAKA` |
| Leading/trailing whitespace | `' Dhaka'` / `'Dhaka '` |
| Spelling mistake | `chitagonj` |
| Typo | ভুলভাবে টাইপ করা value |
| Alternative naming | `Chittagong` / `Chattogram` |
| Word-order variation | `south korea` / `korea south` |
| Same category-এর different writing | একই value-এর ভিন্ন textual form |

তাই categorical text data ব্যবহার করার আগে inconsistent entries **identify এবং standardize** করা গুরুত্বপূর্ণ।

---

# 2. প্রথম কাজ: Inconsistency Identify করা

Data cleaning-এর আগে categorical column-এর values inspect করতে হবে।

### ১. শুধু Unique Values

```python
df['city'].unique()
```

### ২. Sorted Unique Values

```python
np.sort(df['city'].unique())
```

### ৩. Lowercase + Whitespace Clean করে Unique Values

```python
np.sort(df['city'].str.lower().str.strip().unique())
```

এই তিনভাবে inspect করলে original values, sorted values এবং case/whitespace variation বাদ দেওয়ার পর remaining inconsistency—তিনটিই সহজে দেখা যায়।

> [!NOTE]
> `unique()` এবং `sort()` data clean করে না; এগুলো শুধু **সমস্যা identify ও inspect করতে সাহায্য করে**।

# 3. Basic Text Normalization বনাম Fuzzy Matching

Inconsistent text handle করার ক্ষেত্রে প্রথমে **Basic Text Normalization** করা হয়, তারপর প্রয়োজন হলে **Fuzzy Matching** ব্যবহার করা হয়।

এখানে **Text Normalization** বলতে numeric data-এর scaling/normalization বোঝানো হচ্ছে না। এটি categorical text-এর বিভিন্ন textual variation-কে একটি consistent form-এ আনার process।

### Basic Text Normalization

Common text normalization-এর মধ্যে থাকতে পারে:

```python
df['city'].str.lower()
df['city'].str.strip()
```

যেমন:

```text
'DHAKA'
' Dhaka'
'dhaka '
```

কে:

```text
'dhaka'
'dhaka'
'dhaka'
```

এ রকম consistent form-এ আনা।

অর্থাৎ:

```text
Raw Text
   ↓
lower()
   ↓
strip() / whitespace cleaning
   ↓
Normalized Text
```

এগুলো deterministic rule দিয়ে সহজেই fix করা যায়।

### Fuzzy Matching

Text normalization-এর পরেও যদি actual spelling বা naming variation থেকে যায়:

```text
'chittagong'
'chitagonj'
```

তাহলে শুধু `lower()` বা whitespace removal দিয়ে problem solve হবে না।

এক্ষেত্রে string similarity ব্যবহার করে কাছাকাছি values খুঁজে বের করা যায়।

```text
Basic Text Normalization
          ↓
Remaining inconsistency
          ↓
Fuzzy Matching
```

> [!IMPORTANT]
> **Text Normalization simple textual/formatting variation কমায়; Fuzzy Matching remaining similar but non-identical strings খুঁজতে সাহায্য করে।**

---

# 4. Fuzzy Matching কী?

Fuzzy Matching হলো এমন একটি technique যার মাধ্যমে দুটি string-এর মধ্যে similarity কতটা আছে তা measure করা যায়।

```text
Exact Matching:
'chittagong' == 'Chittagong' → False

Fuzzy Matching:
'chittagong' ↔ 'chitagonj'
```

এখানে strings exactly same না হলেও similarity-এর ভিত্তিতে compare করা যায়।

সাধারণভাবে similarity score:

```text
100 → very high similarity / exact match হতে পারে
0   → very low similarity
```

> [!NOTE]
> Score-এর exact অর্থ selected scorer-এর algorithm-এর ওপর নির্ভর করে।

---

# 5. Edit Distance কী?

Fuzzy Matching বোঝার জন্য **Edit Distance** একটি গুরুত্বপূর্ণ ধারণা।

একটি string-কে অন্য string-এ convert করতে কতগুলো edit operation প্রয়োজন, সেটিই Edit Distance-এর মূল ধারণা।

### প্রধান Edit Operations

| Operation | কাজ | উদাহরণ |
|---|---|---|
| **Insert** | নতুন character যোগ করা | `apple` → `sapple` |
| **Delete** | character মুছে ফেলা | `apple` → `aple` |
| **Substitute** | একটি character অন্যটি দিয়ে replace করা | `apple` → `appla` |

### Insert

```text
'apple'
'sapple'
```

এখানে `s` insert করা হয়েছে।

### Delete

```text
'apple'
'aple'
```

এখানে একটি `p` delete করা হয়েছে।

### Substitute

```text
'apple'
'appla'
```

এখানে `e` → `a` করা হয়েছে।

---

# 6. Levenshtein Distance

Levenshtein Distance হলো Edit Distance-এর একটি বহুল ব্যবহৃত form।

এটি সাধারণত **insertion, deletion এবং substitution-এর minimum সংখ্যা** গণনা করে একটি string-কে অন্য string-এ transform করার cost বোঝায়।

### উদাহরণ

```text
'cat'
'cut'
```

শুধু:

```text
a → u
```

একটি substitution দরকার।

তাই:

```text
Levenshtein distance = 1
```

> [!IMPORTANT]
> **Fuzzy Matching = broader matching idea**  
> **Levenshtein Distance = একটি নির্দিষ্ট distance measure**
>
> Fuzzy Matching-এর সব scorer একইভাবে শুধু Levenshtein Distance ব্যবহার করে—এমন নয়।

---

# 7. Similarity Score / Ratio

Fuzzy matching system সাধারণত string similarity বোঝাতে একটি score দেয়।

উদাহরণ:

```text
'chittagong'
'chitagonj'
```

ধরা যাক score:

```text
84
```

অর্থাৎ selected scorer-এর হিসেবে strings দুটি যথেষ্ট similar।

> [!IMPORTANT]
> **High similarity মানেই guaranteed same category নয়।**

যেমন:

```text
'austria'
'australia'
```

Spelling কাছাকাছি হলেও real-world meaning আলাদা। তাই fuzzy score decision-এর একমাত্র ভিত্তি হওয়া উচিত নয়।

# 8. `thefuzz` Library

Python-এ `thefuzz` library ব্যবহার করে fuzzy matching করা যায়।

```python
from thefuzz import process, fuzz
```

| Component | কাজ |
|---|---|
| `process` | matching operation-এর জন্য |
| `fuzz` | বিভিন্ন similarity scorer-এর জন্য |

সবচেয়ে গুরুত্বপূর্ণ functionগুলোর একটি:

```python
process.extract()
```

---

# 9. `process.extract()` কী করে?

`process.extract()` একটি query string-এর সাথে multiple candidate strings compare করে এবং best matching results return করে।

### Basic Syntax

```python
process.extract(
    query,
    choices,
    limit,
    scorer
)
```

---

# 10. `query`, `choices`, `limit`, `scorer`

## `query`

Target/reference string যার সাথে অন্য strings-এর similarity check করা হবে।

```python
query = 'chittagong'
```

অর্থাৎ `chittagong`-এর সাথে কোন candidate city names সবচেয়ে similar তা খোঁজা হবে।

## `choices`

Candidate strings-এর collection, যাদের সাথে query compare হবে।

```python
df['city'].unique()
```

একই value অনেকবার থাকলে প্রতিটি row-এর ওপর matching না করে unique values ব্যবহার করা practical optimization:

```text
1,000,000 rows
      ↓
300 unique values
      ↓
Fuzzy Matching
```

> [!NOTE]
> `unique()` ব্যবহার করা একটি practical optimization; সব workflow-এ এটি বাধ্যতামূলক নয়।

## `limit`

কতটি top matching result return করা হবে।

```python
limit=3
```

`limit` match accept/reject করে না; এটি শুধু output quantity control করে।

## `scorer`

দুটি string কীভাবে compare করা হবে তা নির্ধারণ করে। Different scorer একই pair-এর জন্য different score দিতে পারে।

---

# 11. `limit` বনাম `threshold`

এই দুইটি concept এক নয়।

| Parameter | প্রশ্ন |
|---|---|
| `limit` | **কতটি result দেখব?** |
| `threshold` | **কোন score-এর match গ্রহণযোগ্য?** |

উদাহরণ:

```text
limit = 3
threshold = 70
```

এর অর্থ:

- সর্বোচ্চ 3টি result return করব
- score 70 বা তার বেশি হলে acceptable match হিসেবে consider করব

```text
limit
  ↓
Output quantity

threshold
  ↓
Acceptance criteria
```

# 12. `scorer` ও Common Scorers

Beginner হিসেবে সব scorer দিয়ে শুরু করার দরকার নেই। একটি practical default workflow:

```text
Raw Text
   ↓
lower() + strip()
   ↓
unique()
   ↓
fuzz.ratio
   ↓
threshold
   ↓
validation
   ↓
mapping / replacement
```

```python
cleaned = df['city'].str.lower().str.strip()

matches = process.extract(
    query,
    cleaned.unique(),
    scorer=fuzz.ratio,
    limit=5
)
```

সাধারণ spelling variation-এর জন্য `fuzz.ratio` একটি ভালো starting point।

### অন্য Scorer কখন দরকার হতে পারে?

| Scorer | বেশি useful যখন |
|---|---|
| `ratio` | সাধারণ character/spelling similarity দরকার |
| `partial_ratio` | একটি string অন্যটির অংশ হলে |
| `token_sort_ratio` | একই words কিন্তু order আলাদা হতে পারে |
| `token_set_ratio` | common tokens গুরুত্বপূর্ণ এবং duplicate token থাকতে পারে |

উদাহরণ:

```text
partial_ratio:
'chittagong' → 'chittagong city'

token_sort_ratio:
'south korea' ↔ 'korea south'

token_set_ratio:
'dhaka dhaka city' ↔ 'dhaka city'
```

> [!NOTE]
> সব scorer মুখস্থ করা দরকার নেই। আগে `lower()` + `strip()` + `fuzz.ratio` + `threshold` দিয়ে শুরু করো; data-এর pattern অনুযায়ী প্রয়োজন হলে scorer বদলাবে।

অর্থাৎ:

```text
matched string
      +
similarity score
```

# 14. False Match কেন Dangerous?

ধরো:

```text
'austria'
'australia'
```

এদের string similarity যথেষ্ট high হতে পারে, কিন্তু real-world meaning আলাদা।

Threshold খুব low হলে ভুল replacement হতে পারে:

```text
'austria'
    ↓
'australia'
```

এটি data quality আরও খারাপ করতে পারে।

> [!WARNING]
> Fuzzy matching-কে **automated suggestion / candidate generation technique** হিসেবে দেখা বেশি নিরাপদ, বিশেষ করে ambiguous data-এর ক্ষেত্রে।

# 15. Mapping এবং Replacement

Fuzzy matching-এর result পাওয়ার পরে standard value-এর সাথে mapping তৈরি করা যায়।

উদাহরণ:

```python
mapping = {
    'chitagonj': 'chittagong',
    'chatgram': 'chittagong',
    'sylhett': 'sylhet'
}
```

তারপর mapping অনুযায়ী data standardize করা যায়।

> [!IMPORTANT]
> **Candidate identification এবং final replacement একই জিনিস নয়।**
>
> Fuzzy Matching candidate খুঁজে দিতে পারে।  
> Final replacement করার আগে candidate verify করা যেতে পারে।

# 16. Validation, Limitations এবং কখন Fuzzy Matching ব্যবহার করবে

Fuzzy Matching-এর result automatically apply করার আগে validation করা জরুরি।

Final values inspect করা যায়:

```python
np.sort(df['city'].unique())
```

যাচাই করতে হবে:

- ভুল category merge হয়েছে কি না
- valid category change হয়েছে কি না
- important category বাদ গেছে কি না

### Limitations

- High similarity ≠ same meaning: `austria` / `australia`
- Threshold ভুল হলে false match বা valid match miss হতে পারে
- String similarity business/domain meaning নিজে থেকে বোঝে না
- Complex naming variation-এ domain knowledge লাগতে পারে

### কখন ব্যবহার করবে?

- spelling mistake / typo আছে
- small text variation আছে
- user-entered data noisy
- একই value বিভিন্নভাবে লেখা হয়েছে
- exact matching কাজ করছে না

### কখন blindly depend করবে না?

- categories semantically খুব different
- ভুল merge-এর cost বেশি
- similarity misleading হতে পারে
- domain meaning গুরুত্বপূর্ণ
- candidate list বড় ও ambiguous

> [!WARNING]
> Fuzzy Matching-কে **candidate generation / suggestion technique** হিসেবে ব্যবহার করা নিরাপদ। Final replacement-এর আগে candidate validate করে তারপর mapping তৈরি করা উচিত।

# 17. পুরো Workflow

Categorical text inconsistency handle করার practical workflow:

```text
Identify
   ↓
Unique Values Inspect
   ↓
Basic Text Normalization
   ↓
Re-check Unique Values
   ↓
Identify Remaining Inconsistencies
   ↓
Fuzzy Matching
   ↓
Select Appropriate Scorer
   ↓
Generate Candidate Matches
   ↓
Apply Threshold
   ↓
Validate Candidate Matches
   ↓
Create Mapping
   ↓
Replace / Standardize Values
   ↓
Final Sanity Check
   ↓
Use Cleaned Categorical Data
```
